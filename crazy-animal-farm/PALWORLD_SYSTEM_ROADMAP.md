# Crazy Animal Farm 종합 시스템 분석 및 개발 로드맵

## 1. 목표

`Crazy Animal Farm`을 현재의 탑뷰·오프라인·싱글플레이 콘셉트로 유지하면서, 팰월드에서 확인되는 핵심 플레이 구조를 단계적으로 재해석한다.

최종 게임의 중심 흐름은 다음과 같다.

`탐험 → 채집·전투·포획 → 동물 성장·파티 구성 → 거점 자동화 → 제작·건축 → 지역·임무·보스 해금 → 교배·연구·종반 성장`

다음 원칙은 전체 개발 기간에 유지한다.

- 다른 게임의 이름, 캐릭터, 그래픽, 사운드, 문구, UI 배치와 수치표를 그대로 복제하지 않는다.
- 시스템의 역할과 상호 의존성만 분석하고 현재 게임의 동물·농장·탑뷰 콘셉트에 맞게 다시 설계한다.
- 브라우저 게임, Phaser, React, Zustand, `localStorage`라는 현재 기술 범위를 유지한다.
- 단계마다 저장 데이터 이전 경로를 먼저 확보하고 기존 저장 슬롯을 가능한 한 보존한다.
- 코드 편집은 Codex가 수행하고 실제 실행·플레이 테스트는 사용자가 수행한다.

## 2. 조사 자료와 적용 우선순위

자료가 서로 다르거나 오래된 수치를 표시할 때는 다음 순서로 판단한다.

1. 공식 Steam 상점과 공식 업데이트 공지
2. wiki.gg의 최신 1.0 변경 기록
3. wiki.gg의 개별 시스템 문서
4. 나무위키의 한국어 분류·개요·월드 설정 설명

wiki.gg 개별 문서에는 이전 버전 수치가 남아 있을 수 있다. 예를 들어 작업 적성, 응축 요구량, 포획 보너스처럼 1.0에서 바뀐 항목은 최신 변경 기록을 우선한다. 나무위키는 전체 시스템의 누락 여부를 확인하는 분류표로 활용하되 세부 수치를 그대로 게임에 적용하지 않는다.

## 3. 두 위키에서 확인한 전체 시스템 범위

### 3.1 플레이어와 생존

- 체력, 보호막, 허기, 스태미나, 온도, 공격력, 방어력, 작업 속도, 운반 중량
- 달리기, 회피, 수영, 활공, 등반·갈고리 이동, 탑승 이동
- 무기, 탄약, 방어구, 장신구, 도구, 내구도, 수리, 장비 희귀도
- 음식 영양, 정신력 회복, 일시 강화 효과, 부패
- 사망 페널티, 드롭 상자, 리스폰, 난이도와 월드 설정

### 3.2 동물 수집과 성장

- 야생 동물의 전투, 약화, 상태 이상, 후방·정확 타격과 포획 확률
- 포획 도구 등급, 포획력, 보조 모듈, 종별 포획 보너스
- 파티, 전체 보관함, 거점 작업 배치의 상호 배타적 상태
- 성별, 레벨, 경험치, 종족 기본치, 개체 잠재력, 패시브 특성
- 9계열 속성, 상성, 액티브 스킬, 동반자 스킬, 종별 전용 장비
- 신뢰도, 부상, 기절·부활, 강화 재료를 이용한 능력치 성장
- 같은 종을 사용하는 응축·등급 성장과 작업 적성 강화
- 교배, 알, 부화기, 스킬·특성·잠재력 유전, 돌연변이
- 특성 교체·성별 변경 등의 후반 개체 편집과 최종 각성
- 알파, 희귀 개체, 필드 우두머리, 포식자형 강적

### 3.3 거점과 동물 생활

- 거점 코어, 범위, 거점 레벨 과제, 복수 거점, 방문 상인
- 동물별 먹이, 허기, 정신력, 피로, 수면, 침대, 휴식 시설
- 감기·염좌·골절·궤양·쇠약·우울 등 질병과 의약품·진료소
- 불 피우기, 물주기, 파종, 발전, 수작업, 채집, 벌목, 채광, 제약, 냉각, 운반, 목장 작업
- 작업 적성 레벨, 작업 우선순위, 작업 강도, 금지 작업, 영구 시설 배치
- 운반 경로, 생산물 회수, 필터형 창고, 빠른 보관, 거점 공용 재료
- 전력망, 발전기, 축전 설비, 냉·난방과 시설 가동 조건
- 구조물 건설, 수리, 노후화, 방어벽, 함정, 경보, 방어 시설
- 무작위 거점 습격과 방어 보상

### 3.4 생산과 경제

- 플레이어 수작업과 동물 작업이 함께 참여하는 생산 대기열
- 작업대, 조립 설비, 용광로, 분쇄, 발전, 제약 등 시설별 요구 적성
- 파종·관개·수확을 거치는 농사, 목장 생산, 요리, 사료 관리
- 기술 포인트, 고대 기술, 핵심 아이템, 제작법 해금
- 일반 화폐, 현상금·특수 화폐, 상인 구매·판매와 개체 거래
- 설계도를 통한 장비 제작과 상위 희귀도 합성
- 거점 연구와 작업 계열별 영구 강화
- 보관 중인 동물을 보내는 원정, 권장 전투력·속성 조합·시간·보상

### 3.5 세계, 탐험과 전투 콘텐츠

- 마을, 상인, NPC, 수기·일지, 메인 임무와 연속 보조 임무
- 현상 수배, 적대 세력, 포로 구조, 범죄·경계 시스템
- 반무작위 던전, 지역별 방, 자원, 보스와 종료 보상

- 낮·밤 속도, 경험치, 포획률, 개체 출현량, 피해량과 회복량

## 4. 현재 게임에 맞춘 변환·제외 범위

### 그대로 역할을 유지할 시스템

- 포획, 파티, 보관함, 개체 성장, 작업 적성, 거점 자동화
- 생존, 제작, 건축, 농사, 목장, 교배, 연구, 원정
- 지도, 탐험, 임무, 상인, 던전, 보스, 습격, 월드 이벤트
- 월드 설정, 저장 슬롯, 도감, 기술과 제작법 해금

### 탑뷰 방식으로 변환할 시스템

- 비행은 자유 고도 이동 대신 장애물·지형 통과와 지역 지름길 능력으로 만든다.
- 활공은 낙하 물리 대신 짧은 공중 이동·틈 건너기 기술로 만든다.
- 갈고리는 벽 등반 대신 지정 지점으로 당겨지는 이동 기술로 만든다.
- 수영·수상 탑승은 물 타일 이동 가능 여부와 이동 속도로 구분한다.
- 3차원 다층 건축은 층 프리셋과 기능 중심의 평면 건축으로 단순화한다.
- 대형 해상 요새와 대공포는 탑뷰 포탑, 경보 구역, 제어 장치 퍼즐로 바꾼다.
- PvP 투기장은 싱글플레이 연속 전투·기록 도전장으로 바꿀 수 있다.

### 현재 범위에서 제외할 시스템

- 온라인 협동, 길드, 플레이어 간 거래, PvP, 전용 서버, 크로스플레이
- 안티치트, 서버 관리자 명령, 음성 채팅, 모드 배포 기능
- 다른 작품의 고유 인물·세력·지역·아이템 이름과 외형

인간 포획·도축처럼 현재 콘셉트와 충돌할 수 있는 기능은 그대로 넣지 않고, NPC 구조·현상금 체포·고용 같은 역할로 치환한다.

## 6. 구현 의존성

시스템을 안정적으로 확장하려면 다음 순서를 지킨다.

1. 동물 한 마리를 종족 데이터가 아닌 고유한 `동물 개체`로 저장한다.
2. 개체의 위치 상태를 `야생 / 파티 / 소환 / 보관 / 거점 작업 / 원정 / 교배` 중 하나로 통제한다.
3. 전투·작업·교배가 같은 개체 능력치와 특성 데이터를 참조하게 만든다.
4. 아이템과 제작법을 데이터 정의로 분리한 뒤 생산·상점·드롭이 같은 정의를 사용하게 만든다.
5. 거점 작업은 시설이 직접 동물을 조종하지 않고 공용 작업 스케줄러를 거치게 만든다.
6. 임무와 기술 해금은 특정 장면 코드가 아니라 조건·보상 데이터로 관리한다.
7. 월드 설정은 시스템 구현 후 덧붙이지 않고 각 계산식이 처음부터 설정값을 참조하게 만든다.
8. 저장 구조가 바뀌는 단계마다 이전 버전 저장을 변환하는 마이그레이션을 추가한다.

## 7. 전체 개발 단계

단계는 기능 수가 아니라 의존성 기준으로 나눴다. 각 단계는 이전 단계의 저장 데이터와 플레이 흐름을 깨뜨리지 않는 상태로 종료한다.

### A. 동행과 포획의 핵심 루프

| 단계 | 작업 | 완료 기준 |
|---|---|---|
| 1 | 포획 동물 파티와 보관함 | 5마리 파티, 전체 보관함, 작업 동물과의 중복 방지, 저장 연동 |
| 2 | 동행 소환과 명령 | 선택 동물 소환·회수, 따라오기, 대기, 지정 공격, 집중 공격, 상태 HUD |
| 3 | 동물 개체 데이터 표준화 | 고유 ID, 성별, 레벨, 경험치, 능력치, 잠재력, 특성, 상태와 저장 마이그레이션 |
| 4 | 동물 성장과 회복 | 경험치 분배, 레벨업, 스킬 학습·3칸 장착, 기절·부활, 신뢰도 |
| 5 | 속성·스킬·동반자 능력 | 9계열 상성, 상태 이상, 액티브 스킬, 쿨다운, 종별 동반자 스킬과 전용 장비 |
| 6 | 포획 시스템 확장 | 포획 도구 등급, 체력·상태·후방 보정, 포획력, 보조 모듈, 종별 포획 보너스 |

### B. 플레이어 전투와 생존

| 단계 | 작업 | 완료 기준 |
|---|---|---|
| 7 | 플레이어 행동 자원 | 스태미나, 달리기·회피·공격 비용, 회복 지연, 장비·설정값 연동 |

## 8. 단계별 공통 완료 조건

모든 단계는 다음 조건을 만족해야 완료로 표시한다.

- 새 데이터가 자동 저장 슬롯과 수동 슬롯 5개에 모두 저장된다.
- 이전 저장 버전을 불러올 때 안전한 기본값 또는 마이그레이션이 적용된다.
- 맵 이동, 메뉴 열기, 저장 후 재접속으로 상태가 중복되거나 사라지지 않는다.
- UI가 월드 입력을 막아야 할 때 입력 충돌이 발생하지 않는다.
- 시스템 수치는 상수 또는 데이터 정의에서 변경할 수 있다.
- 임시 도형·색상 자산도 나중에 교체할 수 있도록 로직과 분리한다.
- Codex는 실행 명령을 수행하지 않고, 사용자가 확인할 명령과 플레이 점검 항목을 전달한다.
