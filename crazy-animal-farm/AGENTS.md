# Crazy Animal Farm 작업 규칙

## 작업 시작 순서

1. 새 Codex 작업·새 대화·다른 컴퓨터에서 시작할 때 저장소 루트의 `CODEX_HANDOFF.md`를 먼저 읽는다.
2. 새 작업을 시작할 때 `PALWORLD_SYSTEM_ROADMAP.md`의 현재 진행 위치와 다음 단계를 확인한다.
3. 새 환경이거나 실행 방법이 필요한 경우 `README.md`의 실행 방법, 조작법, 알려진 사항을 확인한다.
4. 같은 대화에서 바로 다음 요청을 이어갈 때는 현재 대화의 최신 작업 상태를 우선 사용하고 위 문서 전체를 매번 다시 읽지 않는다.
5. 대화가 요약·압축되었거나, 외부에서 파일이 변경되었거나, 현재 단계가 불확실할 때만 관련 인계 문서와 변경된 파일을 다시 확인한다.
6. 현재 코드와 문서가 다르면 코드와 저장 데이터 호환성을 확인한 뒤 인계 문서를 갱신한다.

## 단계 진행 규칙

- 별도 요청이 없으면 `PALWORLD_SYSTEM_ROADMAP.md`의 한 단계씩 진행한다.
- 단계의 코드 구현이 끝나면 `CODEX_HANDOFF.md`, `PALWORLD_SYSTEM_ROADMAP.md`, `README.md`를 함께 갱신한다.
- 사용자가 실행 점검 성공을 알려주기 전에는 해당 단계를 정식 완료(`[x]`)로 표시하지 않는다.
- 정식 완료 시 42단계 중 완료 수와 남은 단계 수를 인계 문서와 응답에 기록한다.
- 저장 구조가 바뀌면 저장 버전을 올리고 이전 자동저장 및 수동 슬롯의 마이그레이션을 제공한다.

## 실행과 검증 분담

- Codex는 코드와 문서를 수정하고, 변경 이유와 사용자 점검 항목을 설명한다.
- `npm install`, `npm run dev`, `npm run check`, 빌드, 린트, 테스트와 플레이 점검은 사용자가 실행한다.
- Codex는 사용자가 전달한 오류를 수정하되, 요청 없이 실행형 검증 명령을 수행하지 않는다.

## 구현 원칙

- React UI, Phaser 월드 로직, Zustand 공유 상태, 데이터 정의와 저장 서비스를 현재 구조에 맞게 분리한다.
- 수치와 콘텐츠는 가능한 한 `src/game/config`와 `src/game/data`에서 조정 가능하게 유지한다.
- 기존 저장 데이터와 현재 플레이 흐름을 깨뜨리지 않는 최소 범위의 변경을 우선한다.
- 임시 그래픽은 나중에 에셋으로 교체할 수 있도록 게임 규칙과 분리한다.
