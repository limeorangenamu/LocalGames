# Crazy Animal Farm — Codex 프로젝트 생성 및 개발 지시서

## 0. 이 문서의 목적

이 문서는 Codex가 `Crazy Animal Farm` 웹 게임 프로젝트를 새로 생성하고, 구조를 설계하며, 단계적으로 구현하도록 지시하는 마스터 작업 명세서다.

이 프로젝트는 팰월드에서 일부 장르적 영감을 얻지만, 원작의 캐릭터·이름·그래픽·UI·사운드·포획 도구 디자인·맵·설정을 복제하지 않는다.  
독자적인 코믹 동물, 거점 자동화, 지역 이동 구조를 가진 2D 탑뷰 웹 게임으로 제작한다.

Codex는 처음부터 모든 기능을 한 번에 억지로 완성하지 말고, 아래 단계와 우선순위에 맞춰 **작동하는 수직 슬라이스(vertical slice)**를 먼저 만든다.

---

# 1. 프로젝트 한 줄 설명

> 제멋대로인 미친 동물들과 싸워 포획하고, 거점에 배치해 자원을 자동 생산하며 여러 지역을 탐험하는 가벼운 2D 탑뷰 웹 게임.

게임 이름:

```text
Crazy Animal Farm
```

---

# 2. 핵심 재미

게임의 핵심 반복 구조는 다음과 같다.

```text
탐험
→ 자원 채집
→ 동물과 전투
→ 체력을 낮춘 뒤 포획
→ 거점 건설
→ 포획 동물을 작업에 배치
→ 자원 자동 생산
→ 장비와 포획 도구 제작
→ 더 위험한 다음 지역 탐험
```

가장 먼저 완성해야 하는 한 사이클은 다음과 같다.

```text
나무와 돌을 채집한다.
→ 포획 캡슐을 제작하거나 얻는다.
→ 미친 토끼와 싸워 체력을 낮춘다.
→ 포획한다.
→ 거점 코어를 설치한다.
→ 벌목 작업에 토끼를 배치한다.
→ 일정 시간마다 목재가 생산된다.
```

이 한 사이클이 완전히 작동하기 전에는 동물 종류, 맵, 건물, 장비를 무작정 늘리지 않는다.

# 3. 기술 스택

다음 기술을 기준으로 프로젝트를 생성한다.

```text
- Vite
- React
- TypeScript
- Phaser 3
- CSS
- Zustand
- npm
```

역할 분담:

```text
Phaser
- 실제 게임 월드
- 플레이어 이동
- 카메라
- 충돌
- 동물 AI
- 전투
- 투사체
- 자원 오브젝트
- 건물 배치
- 맵 이동

React + CSS
- 메인 메뉴
- HUD
- 체력바
- 인벤토리
- 포획 동물 목록
- 건설 메뉴
- 거점 작업 관리
- 설정
- 저장/불러오기 안내

Zustand
- Phaser와 React가 공유해야 하는 UI 상태
- 플레이어 체력
- 인벤토리 표시용 데이터
- 선택한 건설물
- 포획 동물 목록
- 현재 맵 이름
```

Phaser 오브젝트를 React DOM 요소로 만들지 않는다.  
게임 속 플레이어, 동물, 나무, 돌, 건물은 Phaser Canvas 안에서 처리한다.

# 4. 새 프로젝트 생성 명령

프로젝트 폴더가 아직 없다면 다음 명령을 실행한다.

```bash
npm create vite@latest crazy-animal-farm -- --template react-ts
cd crazy-animal-farm
npm install
npm install phaser zustand
```

그 후 개발 서버 실행 명령은 다음과 같다.

```bash
npm run dev
```

Codex는 생성된 기본 예제 코드와 사용하지 않는 Vite 로고, 데모 CSS를 제거한다.

# 5. 프로젝트 설계 원칙

## 5.1 작동하는 기능을 먼저 만든다

처음부터 완성된 그래픽을 넣지 않는다.

초기 그래픽:

```text
플레이어 = 파란 원 또는 단순 임시 PNG
적대 동물 = 빨간 원
포획된 동물 = 초록 원
나무 = 초록색 도형
돌 = 회색 도형
거점 코어 = 노란 사각형
건물 = 갈색 사각형
```

플레이 감각과 시스템이 확정된 다음 PNG 또는 스프라이트 시트로 교체한다.

## 5.2 데이터 중심으로 설계한다

동물마다 별도의 클래스를 새로 복사해서 만들지 않는다.

공통 `Animal` 클래스와 `AnimalDefinition` 데이터를 사용한다.

예시:

```ts
type AnimalDefinition = {
  id: string
  name: string
  maxHp: number
  moveSpeed: number
  attackDamage: number
  attackRange: number
  detectionRange: number
  captureDifficulty: number
  behaviorType: 'passive' | 'aggressive' | 'coward'
  workSkills: {
    logging?: number
    mining?: number
    farming?: number
    carrying?: number
  }
}
```

동물 추가는 코드 복사가 아니라 데이터 추가로 가능해야 한다.

동일한 원칙을 다음 대상에도 적용한다.

```text
- 자원
- 아이템
- 건물
- 맵
- 제작법
```

## 5.3 수치와 화면 표현을 분리한다

게임 로직과 Phaser 화면 표현을 가능한 한 분리한다.

예:

```text
AnimalDefinition = 동물 원본 데이터
AnimalRuntimeState = 현재 체력과 상태
AnimalEntity = Phaser 화면 오브젝트
```

## 5.4 기능 간 결합을 줄인다

다음 시스템을 독립적인 관리자 또는 서비스로 분리한다.

```text
- MapManager
- ResourceManager
- AnimalManager
- CombatSystem
- CaptureSystem
- BuildingSystem
- BaseManager
- WorkManager
- SaveService
```

처음부터 과도하게 복잡한 추상화를 만들 필요는 없지만, 한 파일에 모든 로직을 몰아넣지 않는다.

## 5.5 처음부터 멀티플레이를 고려하지 않는다

첫 버전은 완전한 싱글 플레이 오프라인 웹 게임이다.

서버, 로그인, 동기화, 실시간 멀티플레이는 구현하지 않는다.

# 7. 화면과 해상도

게임은 데스크톱 브라우저를 우선 대상으로 한다.

기준 게임 해상도:

```text
1920 × 1080
```

Phaser Scale 설정:

```text
- FIT 방식
- 화면 중앙 정렬
- 브라우저 크기에 맞게 확대/축소
- 게임 내부 좌표계는 1920 × 1080 기준 유지
```

브라우저 창 크기가 달라져도 게임 내부 비율이 찌그러지지 않아야 한다.

Canvas 자체의 CSS 크기와 실제 렌더링 해상도를 구분한다.  
고해상도 화면에서 흐려지는 문제가 생기지 않도록 Phaser 렌더러와 스케일 설정을 명시한다.

초기에는 데스크톱 키보드와 마우스만 지원한다.  
모바일 터치 조작은 첫 버전 범위에서 제외한다.

---

# 8. 조작 방식

초기 조작은 다음을 사용한다.

```text
WASD 또는 방향키 = 이동
마우스 왼쪽 클릭 = 기본 공격
E = 가까운 오브젝트 상호작용 또는 아이템 줍기
Q = 포획 모드 전환
포획 모드 상태에서 왼쪽 클릭 = 포획 캡슐 투척
B = 건설 모드 열기/닫기
R = 건설물 회전
Esc = 현재 모드 취소 또는 패널 닫기
F5 또는 자동 저장 시점 = 저장
```

마우스 오른쪽 버튼은 브라우저 기본 메뉴 문제 때문에 첫 버전 핵심 조작으로 사용하지 않는다.

플레이어는 8방향으로 움직일 수 있다.  
첫 버전에서는 방향별 애니메이션 없이도 된다.

# 9. 월드 및 맵 구조

## 9.1 하나의 거대한 오픈월드를 만들지 않는다

월드는 여러 지역 맵으로 나눈다.

초기 월드 예시:

```text
초원
→ 바위 협곡
→ 중앙 숲
→ 늪지
```

첫 구현에서는 다음 두 지역만 만든다.

```text
1. 초원
2. 바위 협곡
```

## 9.2 맵 이동

맵 가장자리 또는 출구 포털에 도달하면 다른 지역으로 이동한다.

이동 과정:

```text
플레이어가 출구에 접근
→ 이동 안내 표시
→ 짧은 페이드아웃
→ 현재 맵 상태 저장
→ 다음 맵 로드
→ 플레이어 입구 위치 배치
→ 페이드인
```

각 맵은 별도 Phaser Scene으로 복사하지 않는다.  
가능하면 하나의 `WorldScene`과 `MapManager`가 현재 맵 데이터를 교체하는 구조를 사용한다.

## 9.3 맵 크기

첫 초원 맵은 플레이어가 한쪽 끝에서 반대쪽 끝까지 약 40~60초 안에 이동할 수 있는 크기로 만든다.

권장 초기 크기:

```text
타일 크기: 32×32
맵 크기: 80×60 타일
실제 월드 크기: 2560×1920
```

맵 크기는 코드 상수 또는 맵 데이터에서 쉽게 변경할 수 있어야 한다.

# 10. 맵 내부 레이어

맵은 다음 레이어 개념으로 구성한다.

```text
1. 바닥 타일
2. 충돌 없는 장식
3. 상호작용 가능한 자원
4. 건물
5. 플레이어와 동물
6. 공격 이펙트와 투사체
7. React HUD
```

## 10.1 바닥

초기에는 실제 타일 이미지 없이 Phaser Graphics 또는 단순 텍스처로 잔디와 길을 표현해도 된다.

장기적으로는 다음 이미지 타일을 사용한다.

```text
- grass
- dirt
- water
- rock-floor
```

## 10.2 장식

작은 풀, 꽃, 작은 돌은 충돌이나 게임 로직이 없는 장식으로 처리한다.

맵을 풍성하게 보이게 하기 위해 모든 장식을 실제 상호작용 오브젝트로 만들지 않는다.

## 10.3 자원

나무, 돌, 광석은 독립된 오브젝트다.  
바닥 이미지에 합쳐 넣지 않는다.

---

# 11. 블록형 월드 사용 여부

마인크래프트처럼 모든 지형을 파괴 가능한 블록으로 만들지 않는다.

추천 구조:

```text
바닥 = 타일맵
나무·돌·광석 = 별도 오브젝트
건물 = 별도 오브젝트
건설 위치 = 보이지 않는 격자에 스냅
```

첫 버전 건설 그리드:

```text
32×32
```

플레이어에게는 비교적 자유롭게 배치하는 것처럼 보이지만, 실제 건물 위치는 가장 가까운 32픽셀 단위로 맞춘다.

지형 파괴, 땅 파기, 블록 쌓기 기능은 구현하지 않는다.

---

# 12. 카메라와 충돌

카메라는 플레이어를 부드럽게 따라간다.

요구사항:

```text
- 맵 바깥을 보여주지 않는다.
- 플레이어가 화면 정중앙에 고정되어 지나치게 흔들리지 않게 한다.
- 필요한 경우 약한 lerp를 사용한다.
```

충돌은 Phaser Arcade Physics를 사용한다.

충돌 대상:

```text
- 플레이어와 맵 경계
- 플레이어와 물/절벽 등 금지 지형
- 플레이어와 큰 자원
- 플레이어와 건물
- 동물과 맵 경계
- 동물과 주요 장애물
```

그래픽 크기와 충돌 박스 크기를 동일하게 강제하지 않는다.

예를 들어 나무 이미지는 크더라도 충돌 영역은 밑동 부분만 사용한다.

# 13. 플레이어 시스템

초기 플레이어 데이터:

```text
최대 체력: 100
이동 속도: 180
기본 공격력: 12
기본 공격 사거리: 70
공격 재사용 시간: 0.45초
```

플레이어 상태:

```text
- idle
- move
- attack
- hurt
- captureAim
- build
- dead
```

첫 버전 사망 처리:

```text
체력 0
→ 화면 페이드
→ 거점이 있으면 거점에서 부활
→ 거점이 없으면 현재 맵 입구에서 부활
→ 체력 완전 회복
→ 인벤토리 손실 없음
```

복잡한 사망 페널티는 나중에 결정한다.

# 14. 야생 동물 시스템

첫 동물:

```text
ID: crazy-rabbit
이름: 미친 토끼
성향: 겁이 많지만 가까이 접근하면 반격
최대 체력: 45
이동 속도: 120
공격력: 8
포획 난이도: 낮음
작업 능력: 벌목 1, 운반 1
```

초기 AI 상태 머신:

```text
IDLE
WANDER
CHASE
ATTACK
FLEE
HURT
STUN
CAPTURED
WORK
REST
```

미친 토끼 행동:

```text
평소에는 주변을 돌아다닌다.
플레이어가 가까이 오면 잠시 도망간다.
공격받으면 일정 시간 반격한다.
체력이 25% 이하이면 다시 도망가려 한다.
포획되면 야생 오브젝트에서 제거되고 플레이어 포획 목록에 추가된다.
```

동물 AI는 매 프레임 복잡한 판단을 하지 않는다.

권장 판단 주기:

```text
0.2~0.4초마다 AI 판단
```

각 동물의 판단 시점을 조금씩 다르게 하여 한 프레임에 모든 AI가 동시에 계산되지 않게 한다.

# 15. 전투 시스템

첫 버전은 단순한 실시간 전투를 사용한다.

플레이어 기본 공격:

```text
- 마우스 커서 방향으로 짧은 근접 공격 판정
- 공격 쿨다운 존재
- 공격 범위 안의 가장 가까운 동물 또는 판정에 닿은 동물에게 피해
```

동물 공격:

```text
- 플레이어에게 접근
- 공격 범위에 들어오면 공격
- 공격 후 쿨다운
```

필수 피드백:

```text
- 피격 시 짧은 색상 변화 또는 깜빡임
- 체력바 감소
- 짧은 넉백
- 공격 쿨다운 동안 중복 피해 방지
```

첫 버전에는 복잡한 무기 조합, 방어구, 속성 상성, 콤보를 넣지 않는다.

# 16. 포획 시스템

동물은 체력이 낮아질수록 포획 확률이 높아진다.

초기 공식은 단순하고 조정 가능하게 만든다.

예시 개념:

```text
기본 포획률
+ 잃은 체력 비율 보너스
+ 상태 이상 보너스
+ 포획 도구 보너스
- 동물 포획 난이도
```

첫 버전 규칙:

```text
동물 체력이 50%보다 높으면 포획 가능성이 매우 낮다.
동물 체력이 30% 이하이면 포획 가능 상태 표시를 한다.
동물 체력이 10% 이하이면 높은 확률을 준다.
최종 확률은 최소 5%, 최대 95%로 제한한다.
```

초기 포획 도구:

```text
이름: 수상한 포획 캡슐
몬스터볼과 다른 형태와 색상으로 표현
소모품
```

포획 모드:

```text
Q 키로 포획 모드 전환
마우스 위치에 예상 투척 방향 표시
왼쪽 클릭으로 캡슐 투척
동물에 충돌하면 포획 판정
성공하면 동물 제거 후 포획 목록 추가
실패하면 동물이 잠시 분노하거나 도망감
```

UI에는 정확한 확률 또는 다음 단계 중 하나를 표시한다.

```text
매우 낮음
낮음
보통
높음
매우 높음
```

초기에는 정확한 퍼센트도 디버그용으로 함께 표시할 수 있다.

# 17. 자원 채집

첫 자원:

```text
나무
- 체력 30
- 파괴 시 목재 5개
- 재생성 60초

돌
- 체력 45
- 파괴 시 돌 4개
- 재생성 90초
```

초기에는 플레이어 기본 공격으로 채집해도 된다.  
도끼와 곡괭이 시스템은 나중에 추가할 수 있다.

자원은 미리 정의된 생성 지점에서 생성한다.

각 생성 지점 데이터:

```ts
type ResourceSpawnPoint = {
  id: string
  resourceType: string
  x: number
  y: number
  respawnAt: number | null
  blockedByBuilding: boolean
}
```

자원이 파괴되면:

```text
자원 오브젝트 제거
→ 아이템 지급 또는 바닥 드롭
→ respawnAt 기록
→ 시간이 지나면 해당 위치 검사
→ 건물이나 금지 오브젝트가 없으면 재생성
→ 막혀 있으면 일정 시간 후 다시 검사
```

각 자원마다 개별 `setInterval`을 만들지 않는다.

`ResourceManager`가 일정 주기마다 재생성 대상만 묶어서 검사한다.

권장 검사 주기:

```text
5초
```

# 18. 거점과 건설

## 18.1 거점 코어

플레이어는 먼저 거점 코어를 설치해야 한다.

초기 규칙:

```text
- 전체 월드에서 거점 1개만 허용
- 현재 맵의 건설 가능 지역에만 설치 가능
- 거점 코어 반경 480픽셀 안에서만 거점 건물 설치 가능
- 거점 코어는 동물 작업 범위와 자원 저장의 중심
```

나중에 최대 거점 수를 늘릴 수 있도록 데이터 구조는 여러 거점을 지원할 수 있게 설계한다.

## 18.2 건설 가능 판정

설치 금지 대상:

```text
- 맵 출입구 주변
- 물
- 절벽
- 보스 구역
- 다른 건물과 겹치는 위치
- 중요한 맵 전환 트리거
- 너무 좁아 접근할 수 없는 위치
```

건설 미리보기:

```text
설치 가능 = 반투명 정상 표시
설치 불가능 = 붉은 반투명 표시
```

건물은 32픽셀 건설 그리드에 스냅한다.

## 18.3 첫 건물

```text

보관 상자
벌목 작업대
동물 침대
```

첫 수직 슬라이스에서는 거점 코어와 벌목 작업대만 실제 기능이 있어도 된다.

# 19. 포획 동물 작업 시스템

첫 버전에서는 동물이 모든 상황을 자유롭게 판단하는 복잡한 생활 AI를 만들지 않는다.

작업 슬롯 방식을 사용한다.

벌목 작업대 데이터 예시:

```text
필요 작업 능력: logging
작업 슬롯: 1개
작업 간격: 5초
생산량: 목재 1개
```

동물 작업 흐름:

```text
포획 목록에서 미친 토끼 선택
→ 벌목 작업대에 배치
→ 토끼가 작업대 접근 지점으로 이동
→ 작업 애니메이션 또는 흔들림 재생
→ 5초마다 목재 1개 생산
→ 거점 보관 자원에 추가
```

첫 버전에서는 실제 주변 나무 하나하나를 찾아가 베지 않아도 된다.

화면 연출과 내부 생산 계산을 분리한다.

나중에 다음 방식으로 확장할 수 있다.

```text
- 실제 자원 노드 탐색
- 운반 작업
- 휴식
- 식사
- 작업 우선순위
```

## 19.1 접근 지점

건물 중심으로 바로 이동하지 않는다.

각 작업 건물에 동물이 서 있을 접근 지점을 둔다.

예:

```text
건물 위치: 500, 300
접근 위치: 500, 350
```

## 19.2 끼임 복구

동물이 일정 시간 이동하지 못하면 다음 순서로 복구한다.

```text
3초 정지
→ 경로 다시 계산
→ 가까운 빈 위치 탐색
→ 작업 취소
→ 그래도 실패하면 거점 코어 근처 안전 위치로 이동
```

초기에는 완전한 A* 길 찾기가 부담되면 단순 직선 이동과 장애물 회피로 시작할 수 있다.  
건물이 늘어나기 전에 격자 기반 A* 구조로 교체할 수 있도록 목적지와 경로 로직을 분리한다.

# 20. 성능 최적화 원칙

## 20.1 화면 밖 개체

화면에서 멀리 떨어진 일반 동물은 정밀 AI와 충돌 계산 빈도를 낮춘다.

```text
가까운 동물
- 이동
- 공격
- 충돌
- 애니메이션
- 자주 AI 판단

먼 동물
- 낮은 빈도로 위치와 상태만 갱신
- 화면에 보이지 않으면 애니메이션 정지 가능
```

## 20.2 공간 검색

동물이나 자원이 많아졌을 때 모든 개체를 매번 전부 검색하지 않는다.

초기에는 단순 배열 검색으로 구현해도 되지만, 다음 교체 지점을 명확히 둔다.

```text
- spatial hash
- grid partition
- quadtree
```

## 20.3 오브젝트 풀

투사체, 피격 이펙트, 바닥 드롭 아이템이 많아질 경우 오브젝트 풀을 사용한다.

초기부터 모든 것을 풀링할 필요는 없지만, 투사체 생성/삭제가 반복되는 구조는 별도 클래스로 둔다.

## 20.4 업데이트 빈도

다음 로직은 매 프레임 실행하지 않는다.

```text
- AI 목표 탐색
- 자원 재생성 검사
- 작업 배정
- 멀리 있는 개체 상태 갱신
- 자동 저장
```

# 21. 저장 시스템

첫 버전은 브라우저 내부 저장을 사용한다.

초기 구현:

```text
localStorage
```

하지만 저장 로직은 `SaveService`에 숨겨서 나중에 IndexedDB로 교체할 수 있게 한다.

저장 데이터 버전을 포함한다.

```ts
type GameSave = {
  version: number
  savedAt: number
  player: PlayerSaveData
  inventory: InventorySaveData
  capturedAnimals: CapturedAnimalSaveData[]
  bases: BaseSaveData[]
  maps: Record<string, MapSaveData>
}
```

저장 대상:

```text
플레이어
- 현재 맵
- 위치
- 체력
- 인벤토리

포획 동물
- 고유 ID
- 동물 종류
- 현재 체력
- 작업 배치 상태

거점
- 위치
- 건물 목록
- 저장 자원
- 작업자 배치

맵
- 제거된 자원
- 자원 재생성 시간
- 설치된 거점/건물
- 처리된 특수 이벤트
```

일반 야생 동물의 모든 위치는 저장하지 않아도 된다.  
맵 진입 시 규칙에 따라 다시 생성할 수 있다.

자동 저장 시점:

```text
- 맵 이동 직전
- 건물 설치 직후
- 동물 포획 직후
- 30초 간격
- 브라우저 종료 전 가능한 범위
```

저장 데이터가 없거나 깨졌을 때 새 게임으로 안전하게 시작해야 한다.

다만 이후 단계를 위한 타입과 구조는 고려한다.

첫 실행 완료 조건:

```text

4. 플레이어를 WASD 또는 방향키로 움직일 수 있다.
5. 카메라가 플레이어를 따라간다.

11. README에 실행법과 현재 구현 기능이 적혀 있다.
```

Phase 0과 Phase 1이 완성된 뒤, Codex는 변경된 파일과 실행 방법을 요약한다.

# 27. 구현 세부 규칙

## 27.1 TypeScript

```text
- any 사용 최소화
- 핵심 데이터 타입 명시
- null 가능성 처리
- 하드코딩 수치는 constants 또는 데이터 파일로 이동
```

## 27.2 React와 Phaser 연결

Phaser 인스턴스는 React 컴포넌트가 마운트될 때 한 번 생성한다.

언마운트 시:

```ts
game.destroy(true)
```

중복 Canvas 생성을 방지한다.

Phaser에서 Zustand 상태를 너무 자주 갱신하지 않는다.  
매 프레임 React 상태를 변경하지 않는다.

## 27.3 이벤트 통신

Phaser와 React 사이 통신은 다음 중 하나로 단순화한다.

```text
- Zustand 액션
- 작은 EventBus
```

두 방식을 무분별하게 섞지 않는다.

초기에는 HUD 데이터에 Zustand를 사용한다.

## 27.4 오류 처리

```text
- 저장 데이터 파싱 실패
- 에셋 로딩 실패
- 정의되지 않은 맵 ID
- 존재하지 않는 동물 데이터
```

위 상황에서 게임 전체가 즉시 중단되지 않도록 기본값과 오류 로그를 제공한다.

## 27.5 주석

초보 개발자도 읽을 수 있도록 핵심 구조에는 한국어 주석을 작성한다.

하지만 코드 한 줄마다 불필요한 주석을 달지 않는다.

# 30. 차별화 방향

이 게임은 단순히 강한 동물을 잡는 게임이 아니다.

핵심 개성:

> 잡은 동물이 충실하게 일하는 것이 아니라, 제멋대로인 미친 동물들을 어떻게든 굴려 농장을 운영하는 게임.

향후 동물 예시:

```text
폭탄 닭
- 채광 속도가 빠르지만 주변 시설에 사고를 냄

과로 토끼
- 벌목 속도가 빠르지만 자주 쓰러짐

절도 너구리
- 운반이 빠르지만 가끔 물건을 숨김

졸린 곰
- 힘이 강하지만 작업 중 자주 잠듦

광기의 오리
- 혼자서는 약하지만 여러 마리 배치하면 생산량 증가
```

첫 수직 슬라이스에서는 이런 부정적 특성을 구현하지 않아도 된다.  
데이터 구조만 향후 `traits`를 추가할 수 있게 열어둔다.
