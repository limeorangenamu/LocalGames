# Crazy Animal Farm Codex 인계 기록

마지막 갱신: 2026-07-20

## 현재 진행 위치

- 전체 로드맵: 42단계
- 정식 완료: 1~8단계 (`8/42`)
- 현재 작업: **9단계 장비 제작 가치 — 코드 작성 완료, 사용자 검증 대기**
- 정식 완료 기준 남은 단계: 34개
- 검증 통과 후 다음 단계: **10단계 생존 규칙 완성**

## 7단계 검증 결과

- 사용자가 스태미나 기능과 후속 TypeScript 수정, 인벤토리 UI 정리가 정상이라고 확인했다.
- 플레이어 행동 자원을 정식 완료(`[x]`)로 반영했다.

## 8단계 검증 결과

- 사용자가 8단계의 실행 및 플레이 검증 완료를 확인했다.
- 전투 장비 체계를 정식 완료(`[x]`)로 반영했다.
- 전체 진행은 `8/42`, 남은 단계는 34개다.

## 9단계 구현 내용

- 일반·고급·희귀·영웅·전설 5단계 장비 희귀도
- 등급별 범위 안에서 생성되는 공격·채집, 방어·쉴드, 최대 내구도 배율
- 기존 장비 종류마다 현재 최고 등급 개체 하나를 유지하고 상위 제작 시 교체하는 호환 구조
- 미친 토끼·몽실 들양·돌진 멧돼지의 사냥·포획 결과별 장비 설계도 전리품 표
- 획득한 설계도를 인벤토리와 제작 작업대에 표시하는 UI
- 같은 설계도 3장을 다음 등급 설계도 1장으로 합성하는 작업대 기능
- 일반 장비는 기존 제작법으로, 상위 장비는 해당 등급 설계도와 증가한 재료 비용으로 제작
- 제작 등급 선택, 현재 보유 등급, 설계도 수량과 합성 가능 여부 표시
- HUD·퀵바·인벤토리·장비 슬롯의 등급 색상과 실제 변동 능력치 표시
- 희귀도 배율을 채집 피해, 근접·원거리 공격, 방어, 쉴드, 내구도와 수리에 연결
- 장비 개체·설계도 보관함을 포함한 저장 v11 및 v1~v10 자동 마이그레이션

9단계는 아직 사용자의 실행 및 플레이 확인 전이므로 `[x]`로 표시하지 않는다. 공식 진행은 계속 `8/42`, 남은 단계 34개다.

## 8단계 구현 내용

- 구리 장검 근접 무기와 사냥용 활 원거리 무기
- 활이 1회 발사할 때 나무 화살 1개를 소비하는 물리 투사체 공격
- 질긴 가죽 갑옷과 구리 투구, 기존 양털 망토·나무 쉴드의 방어 장비화
- 장착 중이고 내구도가 남은 방어구의 방어력 합산
- `피해 × 100 / (100 + 방어력)`을 반올림하고 최소 1 피해를 보장하는 피해 공식
- 방어 계산 후 쉴드가 피해를 먼저 흡수하고 기존 지연·자동 회복을 유지하는 흐름
- 무기 사용 시 주무기, 동물 피격 시 투구·갑옷·망토·쉴드의 내구도 감소
- 내구도 0에서 자동 해제하고 맨손으로 전환하는 파손 처리
- 장비별 고정 재료를 원자적으로 소비하고 최대 내구도로 복구하는 수리
- 제작법 5종: 구리 장검, 사냥용 활, 나무 화살 묶음, 질긴 가죽 갑옷, 구리 투구

- 장비 내구도 저장과 저장 v10, 기존 v1~v9 자동 마이그레이션

## 7단계 후속 수정 기록

검증 중 수정 기록:

- `Hud.tsx`에서 `breakdown`의 존재만으로 `preview`가 null이 아니라고 TypeScript가 추론하지 못한 TS18047 오류를 수정했다. 상태 이상 목록과 후방 판정을 안전한 기본값으로 분리했다.
- 제작법 탭의 스크롤 위치가 인벤토리에 남지 않도록 탭 콘텐츠를 교체 렌더링하고 상위 공용 스크롤을 제거했다.
- 데스크톱 인벤토리는 보유 아이템 그리드만 독립 스크롤하며 플레이어·장비 패널은 고정된다.
- 제작 안내와 반복 설명, 현재 사용하지 않는 장비 슬롯을 제거하고 주무기·망토·쉴드 및 스태미나·포획력·포획 모듈만 표시한다.
- 보유 아이템은 기본 40칸만 렌더링하고 항목이 증가할 때 최대 64칸까지 그리드가 확장된다.

## 불러오기 안전성 후속 수정

문제 원인:

- 기존 흐름은 전환 직전 현재 진행을 자동저장에만 남겼다.
- 다른 기록으로 플레이하면 주기 자동저장이 같은 자동 슬롯을 덮으므로 이전 진행이 사라질 수 있었다.
- 슬롯 전환 새로고침의 `beforeunload` 자동저장도 불러올 자동 슬롯 자체를 덮을 가능성이 있었다.

수정된 흐름:

1. 불러올 기록이나 새 게임 슬롯을 먼저 선택한다.
2. 현재 진행을 보관할 별도의 수동 슬롯 1~5를 선택한다.
3. 기존 기록이 있는 수동 슬롯은 덮어쓰기 확인을 한 번 더 받는다.
4. 실제 저장 성공 응답을 받은 뒤에만 선택한 기록으로 전환한다.
5. 불러올 대상 슬롯은 백업 대상으로 사용할 수 없다.
6. 현재 진행을 버려도 괜찮은 경우에만 경고를 확인하고 `저장하지 않고 전환`한다.
7. 의도적인 전환에서는 종료 자동저장을 실행하지 않는다.

## 사용자 검증 대기 항목

8단계 자체는 완료되었고, 불러오기 안전성 후속 수정과 9단계 코드가 검증 대기다. Codex는 실행하지 않는다. 사용자가 다음을 수행하고 결과를 전달한다.

```bash
npm run check
npm run dev
```

플레이 점검:

1. 옵션의 불러오기 탭에서 기록 또는 빈 슬롯을 선택하면 현재 진행 보관 안내와 수동 슬롯 1~5가 표시되는지 확인한다.
2. 불러올 대상이 수동 슬롯이면 같은 슬롯을 백업 대상으로 선택할 수 없는지 확인한다.
3. 빈 수동 슬롯을 고르면 현재 진행 저장이 완료된 뒤 선택한 기록 또는 새 게임으로 전환되는지 확인한다.
4. 기존 수동 슬롯을 고르면 덮어쓰기 확인 후 저장과 전환이 이어지는지 확인한다.
5. 전환 뒤 백업 수동 슬롯을 다시 불러왔을 때 전환 전 진행이 복원되는지 확인한다.
6. `저장하지 않고 전환`은 복구 위험 경고를 확인한 뒤에만 실행되는지 확인한다.
7. 자동저장 슬롯을 불러올 때 종료 직전 현재 진행으로 대상 자동저장이 덮이지 않는지 확인한다.
8. 동물을 사냥하거나 포획할 때 낮은 확률로 장비 설계도가 드롭되고 인벤토리에 표시되는지 확인한다.
9. 제작 작업대에서 보유한 설계도의 등급을 선택할 수 있고 등급에 따라 요구 재료가 늘어나는지 확인한다.
10. 같은 설계도 3장을 합성하면 다음 등급 1장이 생기며 최고 등급은 더 합성되지 않는지 확인한다.
11. 상위 등급 장비 제작 후 HUD·퀵바·인벤토리·장비 슬롯에 등급이 표시되는지 확인한다.
12. 상위 장비의 공격·채집·방어·쉴드·최대 내구도 수치가 실제 플레이에 반영되는지 확인한다.
13. 저장 후 새로고침했을 때 장비 등급·변동 수치·설계도 수량이 유지되는지 확인한다.
14. 기존 v10 슬롯이 v11로 불러와지고 기존 장비가 일반 등급으로 유지되는지 확인한다.
